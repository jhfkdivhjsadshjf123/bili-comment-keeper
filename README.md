# B站评论管家（BiliComment Keeper）

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Manifest](https://img.shields.io/badge/manifest-v3-brightgreen.svg)](manifest.json)
[![Chrome](https://img.shields.io/badge/chrome-116%2B-yellow.svg)](#安装chrome--edge)
[![Dependencies](https://img.shields.io/badge/dependencies-0-success.svg)](manifest.json)
[![检查](https://github.com/jhfkdivhjsadshjf123/bili-comment-keeper/actions/workflows/check.yml/badge.svg)](https://github.com/jhfkdivhjsadshjf123/bili-comment-keeper/actions/workflows/check.yml)

弥补 B 站没有「查看自己的评论历史」的功能。

**它是一个本地评论库，顺带能删。**

核心是**把你发过的所有评论收进本地、能搜能筛能导出备份** ——
删除只是库里其中一个可选操作，因为管理才是长期需求，删完就没了。

所有数据都在你自己的浏览器里，**没有服务器、没有账号、零上报**。

---

## 它做五件事

| | 做什么 |
| --- | --- |
| **① 收进本地库** | 抓到的一切都存在扩展本地（`chrome.storage.local`）。每条带正文、时间、属于哪个视频、是几级评论、**还活着没有**、**上次检查是什么时候**，以及**是自己记录的还是导入的** |
| **② 自动记录新评论** | 你在 B 站发出任意一条评论（含楼中楼回复），扩展立刻把它写进库 —— 不需要任何额外操作 |
| **③ 巡检存活** | 逐条**只读地**问 B 站「这条还在不在」。几千条里往往一大半早就没了，这一步把它们筛出去，剩下的才是真正要管的 |
| **④ 导出备份** | 一键导出 JSON（可再导入）、HTML（双击离线翻看）、Markdown（丢进笔记）。定期导一份，哪天扩展没了、账号出事了，记录还在你手里 |
| **⑤ 需要时删除** | 在库里勾选 → 放进删除队列 → 核对后执行。删成功的在库里标成「已删除」留一条账，方便事后核对 |

**什么情况下特别有用：**

- 你想知道自己这些年在 B 站都说了些什么（B 站自己不给看）
- 你想在删号 / 退网之前留一份记录
- 你要清理历史评论，但**不想盲删** —— 先看清楚哪些还在、哪些是黑历史
- 你担心哪天评论被删、账号出事，手里没底

## 三个页面

控制台开在浏览器**侧边栏**里（跟着窗口走，比标签页稳）。顶栏三个入口：

```
┌ 评论管家                        [导入历史] [数据] [设置] ┐

主页 = 所有历史评论（日常都在这）
  概览：库里 / 还在 / 已没了 / 已删除 / 查不到 / 未检查
  搜索正文·rpid·视频号 ┃ 来源筛选 ┃ 排序 ┃ 状态筛选 ┃ 分页列表
  巡检存活 · 删除选中 · 拉视频标题 · 导出 / 导入
  ▸ 删除执行（可选操作，折叠）
  ▸ 已删除记录（折叠）
  ▸ 运行日志（折叠）

导入历史（一次性初始化，平时用不到）
  自动翻页抓取 · 读当前页 · 清掉没了的 · 清空导入

数据与存储（数据都在哪、各占多少、怎么删）
  ① 评论库  ② 设置  ③ 导出的备份文件  ④ 不保存什么
```

另外，**B 站自己的消息页**（`message.bilibili.com`）左侧栏会多出一栏「我的评论」——
详见下面「在 B 站自己的消息页里看」。

## 一、安装（Chrome / Edge）

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**，选中本文件夹

> 需要 **Chrome 116 或更高版本**（用到了 MV3 的主世界内容脚本和侧边栏）。
> 侧边栏打不开时（企业策略等）会自动退回成一个标签页，功能一样。

**从 Release 下载 zip 的话**：解压之后，**要选那个里面直接能看到 `manifest.json` 的文件夹**。
选错了会报「**清单文件丢失或不可读取**」—— 那就是选到了外层，往里再点一层就好。

> **升级时请对着 `chrome://extensions/` 里原来那一条点「重新加载」，不要重新下载 zip 再加载一遍。**
> Chrome 给「已解压扩展」分配的 ID 是按**文件夹路径**算的 —— 换一个文件夹加载等于装了一个
> **全新的扩展**，`chrome.storage.local` 里的评论库会从零开始。
> （升级前先导出一次 JSON 备份是最稳的。）

### 它要了哪些权限？

装之前 Chrome 会弹权限提示，这里逐条交代：

| 权限 | 用来干什么 | 为什么绕不开 |
| --- | --- | --- |
| `storage` | 存评论库（`chrome.storage.local`）和设置 | 这就是"本地库"本身 —— 没有它就没有这个产品 |
| `scripting` | 往 bilibili 标签页注入一小段脚本 | 删除请求必须从 bilibili 页面里发出去，否则登录态 Cookie 会被 SameSite 拦掉 |
| `sidePanel` | 把控制台开在浏览器侧边栏 | 侧边栏跟着窗口走，比「必须一直开着一个标签页」稳得多 |
| `bookmarks` | **可选功能**：把评论同时写一份到浏览器收藏夹 | 默认**关闭**。数据本来存在本地库里，不需要收藏夹 —— 留着是为了让你在书签里也能翻到 |
| 主机权限 `https://*.bilibili.com/*` | 在 B 站域名下运行 | 抓评论接口、发删除请求都只发生在 B 站 |
| 主机权限 `https://*.aicu.cc/*` | **只在你自己打开 aicu.cc 时**运行 | 见「导入历史」一节 |

**故意没有申请的权限**（这些才是该警惕的）：

- **没有** `tabs` / `webNavigation` —— 读不到你的浏览历史
- **没有** `webRequest` / `declarativeNetRequest` —— 不能监听或篡改你的网络请求
- **没有** `<all_urls>` —— 只在 B 站和 aicu.cc 上运行，别的网站一概不碰
- **没有**远程代码 / 外部服务器 —— 零依赖、零上报，所有代码都在本地

**关于 `bookmarks`**：它确实能看到你的全部书签，这是权限本身决定的。扩展的行为边界是：
**只在自己创建的那个目录里增删书签**，而且只有你在设置里打开镜像之后才会碰它。

**关于 aicu.cc 那条权限**：扩展在 aicu.cc 上**不会替你发任何请求**，只是挂钩页面自己的
`fetch` / `XMLHttpRequest`，把页面**已经拉回来**的评论列表读一份走 ——
和你打开页面看到的是同一份数据，不会给 aicu.cc 增加任何额外负载。

## 二、怎么用

### 记录新评论（装好就自动生效）

正常刷 B 站、正常发评论就行。

发完之后打开控制台，评论库里**立刻**多出一条，带 <kbd>记录</kbd> 标签 ——
不需要刷新页面，也不需要重开面板。

- 楼中楼回复也会被记录
- 库里存的是**结构化数据**（正文、时间、oid、type…），不是一条书签
- 面板关着的时候发的评论也会记下来，下次打开就在

> **刚装完扩展时，已经开着的 B 站标签页不生效** —— 内容脚本是随页面加载的。
> 刷新一下那个页面（或重新打开）再发。这是浏览器扩展的通用限制，不是这个扩展的问题。

### 巡检存活 —— 最该先做的一步

几千条历史评论里，**往往一大半早就没了**（自己删过、被删过、视频没了…）。
先让扩展逐条问一遍 B 站，把已经没了的筛出去。

点 **「巡检存活」**：

- 这一步是 **100% 只读的**（`GET /x/v2/reply/reply`），不会删任何东西
- 每条之间的间隔只有 0.35 秒 —— 因为只读请求对风控的压力比删除小一个量级
- 面板上有**进度条**，而且列表和数字**每秒自己刷新**，不用管它
- 中途可以点 **停止**，探过的都记着，下次接着来
- **探测绝不会误杀**：风控、超时、会话太长没翻完，一律记成「查不到」，
  宁可留着让后面删一次，也不会把还活着的评论漏判成"没了"
- **不需要登录**：查评论的接口是公开可读的（别人本来也能查你的评论）

**它查的是你当前筛选出来的那一栏。** 按钮上的字会跟着变：

| 当前选中的筛选 | 实际检查 | 按钮 |
| --- | --- | --- |
| 未检查 | 还没探过的 | 巡检存活 |
| 已检查 | 还在 + 查不到 | 重新检查 |
| 还在 | 还在的 | 重新检查 |
| 查不到 | 查不到的 | 重新检查 |
| 全部 | 还在 + 查不到 + 未检查 | 检查全部 |
| **已没了** | —— | **灰的，点不动** |
| **已删除** | —— | **灰的，点不动** |

「已没了」和「已删除」的结论是**确定**的（一条确认没了、一条是你自己删的），
重问一遍既浪费请求也问不出新东西 —— 所以它们既不能单选着查，
也不会被「全部」顺带扫进去。

> 日常用法：先选 **「未检查」**（第一次跑就是这一栏），点 **巡检存活**。
> 过一阵子想看看「还在的那些现在还在吗」，就选 **「已检查」** 或 **「还在」**，再点一次。

跑完之后，库里每条都会带上状态：

| 状态 | 意思 |
| --- | --- |
| <kbd>还在</kbd> | 确认还活着 |
| <kbd>已没了</kbd> | 确认没了（自删 / 被删 / 视频没了） |
| <kbd>查不到</kbd> | 问不出结论（视频不可访问、评论区关闭、风控…）—— **不等于没了** |
| <kbd>未检查</kbd> | 还没探过 |
| <kbd>已删除</kbd> | **本扩展删成功的**，留一条账 |

### 搜索、筛选、导出

- **搜索**：正文、rpid、视频号（BV/av）都能搜
- **来源筛选**：全部来源 / <kbd>记录</kbd>（自己刚发的）/ <kbd>导入</kbd>（aicu 历史）
- **排序**：时间新→旧 / 时间旧→新 / 按视频
- **状态筛选**：全部 / 已检查 / 还在 / 已没了 / 已删除 / 查不到 / 未检查

**导出**在库的下方，三种格式：

| 格式 | 用途 |
| --- | --- |
| **JSON** | 完整备份，**可以再导入回来**。换电脑、扩展重装都靠它 |
| **HTML** | 自包含单文件，双击离线翻看，带样式和状态标签 |
| **Markdown** | 丢进笔记软件（Obsidian / Notion 之类） |

导出的文件直接下到**你自己的下载目录**，扩展管不着、也不会偷偷删。

> **定期导一份 JSON。** 本地库在扩展的存储里，卸载扩展就会一起没。
> 导出的文件才是真正属于你的那份。

### 在 B 站自己的消息页里看（「我的评论」那一栏）

打开 B 站原生的消息页 `https://message.bilibili.com/#/reply`，
左侧栏会多出一栏 **「我的评论」**，就在「我的消息」和「回复我的」中间：

```
消息中心
  我的消息
  我的评论      ← 扩展加的
  回复我的
  @ 我的
  收到的赞
  系统通知
  ───────────
  消息设置
```

点进去就是**库里「还在」的那些评论**（巡检确认过仍然存在的），
每条带正文、视频、类型、时间和 rpid，右边一个「打开」直接跳到那条评论。

- 只读，**不会改你 B 站上的任何东西**
- 那一栏是插进 B 站原生侧栏里的，用的是**它自己的样式类**，
  所以看起来就是原生的（亮色 / 暗色主题都跟着走）
- 点它自己的栏目（「回复我的」等）就自动让位，不会赖着
- 最多显示最近 200 条；更早的、以及已没了 / 已删除的，去控制台看

**每条右边有「删除」**（鼠标悬停才变红，免得误点）。点它弹一句「删除后不可恢复」，
确定就**当场删掉这一条** —— 不走控制台那套批量流程，同时本地记成「已删除」，
控制台的「已删除」+1、这一栏少一条。

**来源那一段显示视频标题**：库里只存了 `type:oid`，直接显示是 `av123456789` 这种没人看得懂的号。
所以打开这一栏时会**按需抓前 12 个视频的标题**（每个视频只抓一次，抓到就进库缓存），
抓不到的退回短标签（`av…` / `cv…` / `t.bilibili.com/…`）。
这也是为什么控制台里没有「拉视频标题」按钮了 —— 需要的地方自己会抓。

> 这一栏的数据由扩展后台算好再送过来 —— 内容脚本是经典脚本，
> 用不了 `store.js` 那套 ES 模块，让后台算就不会把「什么算还在」这套判断抄第二遍。

### 账号绑定（很重要）

这个扩展**绑定一个 B 站账号**，绑定是自动的：

> 只要你登录着访问过一次 bilibili.com，扩展就从 B 站自己的登录态里
> 读出你的 UID（`GET /x/web-interface/nav` 里的 `data.mid`），**不用手输**。

**为什么必须认这个：** aicu 的地址是 `aicu.cc/reply?uid=xxx` ——
把 `uid` 一换，读到的就是**别人的评论**。导进库里之后，
「删除选中」会拿着别人的 rpid 去发删除请求，账也全乱了。

所以有准入规则：

| 情况 | 行为 |
| --- | --- |
| 还没认出你是谁 | **什么都不导**，提示先把 UID 认出来 |
| UID 和你自己的一样 | 正常导入 |
| UID 是你确认过的小号 | 正常导入 |
| UID 是陌生的 | **一条都不写**，问一句「这是你的小号吗？」 |

答「是」→ 记进小号列表，并把刚才拒掉的那批补进去；
答「不是」→ **什么都不做，一点痕迹都不留**。

要换账号：去「数据」页删掉整个评论库（这会连账号绑定一起解除），
然后用新账号访问一次 B 站即可。

### 导入历史（首次使用时的初始化步骤）

本扩展只能记录**装好之后**发出的评论 —— 装之前发的、在手机 App 上发的，
它一无所知。要把那些也收进库里，可以从 [aicu.cc](https://www.aicu.cc)
（一个第三方 B 站评论查询站）把历史清单导进来。

> **这是一次性的初始化步骤，不是日常功能。** 所以它没放在主页上，
> 而是收在顶栏的 **「导入历史」** 按钮里。

**怎么做：**

1. 在浏览器里打开 `https://www.aicu.cc/reply?uid=你的UID`
2. 控制台 → 顶栏 **「导入历史」**
3. 点 **自动翻页抓取** —— 扩展会替你把页面上的「下一页」一页页点下去
   （也可以自己手动翻，扩展只读你实际翻到的那几页；只想要眼前这一页就点 **读当前页**）
4. 点 **「← 返回评论库」**，抓进来的评论已经在库里了
5. 建议接着点 **巡检存活** 筛一遍

**几点必须说清楚：**

- **aicu.cc 只是索引，评论实体在 B 站。** 删除永远发生在 B 站，
  不可能从 aicu 的存档里删东西；而且这类站点往往自己留了副本，
  你把 B 站评论删了，它的存档也未必跟着消失。
- **扩展不会替你多发一个请求。** 它只是挂钩 aicu 页面自己的
  `fetch` / `XMLHttpRequest`，把你**已经翻到**的那几页数据读一份走。
  自动翻页也只是"替你去点下一页"，走的是 aicu 自己那套完整流程。
- 翻页时报错或列表一直转圈，那是 aicu 自己的排队 / 验证没过，与本扩展无关。

### 删除（可选操作）

**先说清楚：删除是库里其中一个操作，不是这个扩展的目的。**
如果你只是想备份，看到这里就够了。

**怎么删：**

1. 在主页的评论库里**勾选**要删的条目（可跨页勾选，也可「全选本页」）
2. 点 **「删除选中」** —— 它们进到下面的「删除执行」队列
3. 核对队列，点 **「删除评论」** 开跑
4. 看进度条、剩余时间和日志；删成功的在库里标成「已删除」

**设计上的几个要点：**

- **不该删的进不了队列**：已经确认「已没了」和「已删除」的会被挡在外面，
  并在界面上说明原因 —— 不为一条本来就不存在的评论浪费一次请求
- **「查不到」是可以进队列的**：它是"问不出结论"，不等于没了
- **每条都要真调一次接口**，默认间隔 1.5~4 秒（可在设置里调）。
  几千条会跑很久 —— 开始前日志里会给出预计耗时，随时可以停
- **复用同一个 bilibili 标签页**发请求，没有现成就开一个后台标签页，跑完关掉
- **开工前自检**：确认能注入页面、能读到登录态、消息链路通，
  免得链子断了演变成「一千多条各等 23 秒」还看不出哪里坏了
- **中途可以点「停止」**：已经处理过的会记账，下次接着跑不会重头再来
- **「已删除记录」是本地账本**：删掉的条目留在库里，可以事后点开核对
  （链接原样保留，点进去能看到 B 站那边的真实情况）

> **「删除评论」和「清空记录」不是一回事**，所以名字分开了：
> 前者删的是 **B 站上的评论**；后者清的是 **本地这条账**。
> 账本不清理也不影响任何功能，所以那个有二次确认。

### 数据与存储

顶栏 **「数据」** 页把「东西都存在哪」一次讲清楚：

| 区块 | 内容 | 能做什么 |
| --- | --- | --- |
| ① 评论库 | 条数明细、涉及多少视频、**本地占用多少 KB** | 导出 JSON / 清掉已删除记录 / **删除整个评论库**（带二次确认） |
| ② 设置 | 当前开关一览 | 恢复默认设置 |
| ③ 导出的备份文件 | 说明文件直接下到你自己的下载目录，扩展管不着也不会偷偷删 | — |
| ④ 不保存什么 | 不存密码、不存 cookie、不记浏览历史 | — |

## 三、它是怎么做到的

> **数据只有一份**：`chrome.storage.local` 里的评论库（`bc_library`）。
> 收藏夹、索引、云同步那套老架构在 v1.7 已经拆掉了，理由见 [CHANGELOG](CHANGELOG.md)。

| 环节 | 实现 |
| --- | --- |
| 认出你是谁 | `src/recorder-main.js` 在 B 站页面上顺手读一次 `GET /x/web-interface/nav`，里面的 `data.mid` 就是 UID |
| 抓评论 | 同一个文件在主世界挂钩 `fetch` / `XMLHttpRequest`，只偷看 `POST /x/v2/reply/add` 的成功响应，从里面取 `rpid / root / parent` |
| 落盘 | `src/background.js` 把这条评论写进评论库（`source: 'record'`、`state: 'live'`） |
| 界面自己刷新 | 面板监听 `chrome.storage.onChanged` —— 任何写入路径都会立刻反映到界面上，不用关掉重开 |
| 巡检存活 | 只读的 `GET /x/v2/reply/reply`。楼中楼靠 `ctime` 二分定位（B 站把每页硬限在 20 条，二分能把 200 条的会话压到 5 次请求） |
| 删除 | 往 bilibili 标签页注入脚本，由**那个页面**发 `POST /x/v2/reply/del`（`type / oid / rpid / csrf`） |
| 同步手动删除 | `src/recorder-main.js` 同时监听 `/x/v2/reply/del` 的成功响应；你在网页上自己删评论时，`src/background.js` 同步把库里那条标掉 |
| 账号准入 | 库里绑定一个主账号；陌生的 UID 一条都不导入，只问一句「是你小号吗」 |
| aicu 导入 | `src/aicu-main.js` 在 aicu.cc 主世界挂钩 `fetch` / `XMLHttpRequest`，把页面**已经拉回来**的响应读走 |
| 自动翻页 | `src/aicu-auto.js` **就是替你去点 aicu 页面上的「下一页」**，走的是 aicu 自己那套流程 |

**为什么删除请求非要绕到 bilibili 页面里发？**
扩展页面的来源是 `chrome-extension://`，对 `bilibili.com` 算跨站，
`SESSDATA` 这类 Cookie 会被 SameSite 规则拦掉，直接发必然未登录。
在 bilibili 页面里发就是同站请求，和 B 站自己前端发的请求一模一样。

**为什么结果不靠内容脚本回传？** 注入的脚本把结果挂在页面的 `window` 上，
控制台自己回来取（主通道）；老路子的 `postMessage` → 内容脚本转发只当兜底。
因为**标签页可能是装/更新扩展之前就开着的**，里面的内容脚本已经失效 ——
主通道没有这个依赖。

## 五、常见问题

**Q：发完评论，库里没出现？**

- 先确认设置里「自动记录评论」是开的
- **刚装完扩展时，已经开着的旧标签页不生效** —— 刷新一下那个页面再发
- B 站偶尔会改接口路径。真漏了可以在设置里打开「剪贴板兜底」，
  然后手动点一下那条评论的「复制评论链接」补记
- 面板不用刷新：库一变界面就自己更新（不用关掉重开）

**Q：我在 B 站网页上自己删了评论，库里会怎样？**
会同步标成「已删除」，「还在」相应减一。
前提是删的那一刻那个页面加载着扩展（扩展装好后**新打开或刷新过**的页面）。
如果是在手机 App 上删的，扩展不知道 —— 在面板里巡检一次就能发现。

**Q：为什么「库里的条数」和「还在的条数」对不上？**
正常。库里存的是**抓到过的一切**，包括早就没了的。
「还在」只统计确认存活的那部分。想知道全貌看主页的概览行。

**Q：为什么有一堆「查不到」？**
「查不到」是**问不出结论**，不等于没了 —— 常见原因：视频被删或设为私密、
评论区被关闭、命中风控限流。它们**可以**进删除队列（删一次就知道了），
也不会被误判成"已没了"。

**Q：删除时报 `-509 请求过于频繁`？**
触发了风控。代码会自动等 15 秒重试一次；还失败就把设置里的间隔调大
（比如 4000~8000 毫秒），过一会儿再点「重试失败项」。

**Q：报 `-101 账号未登录` / `-111 csrf 校验失败`？**
浏览器里的 B 站登录态过期了。重新登录 B 站，然后重试。

**Q：报「自检没通过」？**

| 提示 | 怎么办 |
| --- | --- |
| 读不到 `bili_jct` | 那个页面没登录态。确认浏览器登录了 B 站，刷新那个页面 |
| 注入脚本卡住 | 那个标签页多半卡住了（后台标签页被冻结、一直没加载完）。扩展会**自己换一个干净的标签页重试**；还不行就关掉那个 bilibili 标签页再点一次 |
| 兜底通道没回应 | **不影响删除**（主通道不走它）。这是提示那个标签页的内容脚本是旧版本，刷新一下就好 |

**Q：一次删太多会不会封号？**
删的是你自己的评论，属于正常操作。但短时间高频操作确实可能触发风控（表现为 -509），
所以默认加了随机间隔。几百条建议分批来。

**Q：「拉视频标题」按钮去哪了？**
v1.12 删掉了那个手动按钮；v1.14 起改成**在需要的地方按需自动抓** ——
打开 B 站消息页的「我的评论」那一栏时，会为眼前这几条补上视频标题，
每个视频只抓一次、抓到就进库缓存。已经缓存过的标题，导出 HTML / Markdown 时也照样会带上。

**Q：导出的时候提示"缺少评论区 oid"？**
极少数条目（比如剪贴板兜底记下来的、或者没有视频号的）拿不到 `oid`。
视频评论会自动用 BV 号反查 aid，一般能救回来；非视频页面（动态、专栏）
如果反查不到，那条删除会很早失败并说明原因，不影响别的。

**Q：aicu 导入区一直是 0 条？**
扩展只读你**实际翻到**的那几页，没有翻页就不会有数据。另外两点：
（1）刚装好或刚更新扩展时，**已经开着的 aicu 页面不生效**，刷新一下再翻页；
（2）翻页时报错或列表一直转圈，那是 aicu 自己的排队 / 验证没过，与本扩展无关。

**Q：我从别人的 aicu 页面导入，扩展拦住了？**
故意的。aicu 的地址换个 `uid` 就是别人的评论 —— 导进你的库里之后，
「删除选中」会拿着别人的 rpid 去发请求，账也全乱。
如果那确实是你的小号，答一句「是」就会放行。

**Q：导入的评论几乎全是「B 站上已经没有这条了」，正常吗？**
正常。aicu 是历史存档，里面很多是你早就删掉的。一遍跑完之后剩下的才是真正需要处理的。

**Q：本地库会不会哪天突然没了？**
会 —— 只要你**卸载扩展**，`chrome.storage.local` 就一起清掉了。
所以**定期导出 JSON**。导出的文件在你自己的下载目录里，谁也拿不走。

**Q：我把浏览器收藏夹里的目录删了，会有影响吗？**
没有。数据在本地库里，收藏夹只是个可选镜像（而且默认关着）。
